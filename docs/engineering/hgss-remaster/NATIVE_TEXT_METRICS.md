# Native text metrics and typography contract (draft for review)

**State:** Task 4 draft. The mechanics below are implemented and reproducible;
the *visual* contract is **not approved yet** and must not be treated as
settled until the maintainer signs off on the specimens listed at the end.

Generated by `tools/fonts/`; review artefacts under
`assets/fonts/generated/specimens/`.

## 1. What the source font actually is

The pinned Galmuri14 BDF (`v2.40.4`, SHA-256 `316afc1e…bf4`) declares:

| Property | Value |
| --- | --- |
| `SIZE` | 21 px strike, 75 dpi |
| `FONTBOUNDINGBOX` | 16 × 22, origin −1,−4 |
| `FONT_ASCENT` / `FONT_DESCENT` | 18 / 3 |
| `POINT_SIZE` | 15 |
| `CAP_HEIGHT` | 14 |
| `X_HEIGHT` | 10 |

So "Galmuri14" names a 14 px cap height, not a 14 px em. The brief's
"15-pixel (11-point) strike" corresponds to `POINT_SIZE 15`; there is no
15 px bitmap strike in the release. The pipeline therefore starts from the
real strike (21 px line box) and never resamples it.

## 2. Placement rule

HGSS logic and layout stay in 256 × 192 units. The interface mapping is 5/4.
Kohjoh places a glyph as:

```text
physical_pen_x = 40 + round(logical_pen_x * 5/4)   (upper screen)
physical_pen_x =      round(logical_pen_x * 5/4)   (lower screen)
physical_cell_y =     round(logical_cell_y * 5/4)
physical_glyph_top =  physical_cell_y + bearing_y
```

`bearing_y` is stored in the atlas as the row of the glyph's top inside the
16-row DS text cell; the baseline is the fixed row 15 of that cell. Only the
**cell origin** is scaled. The glyph mask is blitted 1:1 at native size, so
strokes stay on whole physical pixels, and advancing the pen accumulates in
logical units (`logical_pen_x += original_advance`) before a single mapping
step. This is the anti-drift rule from the brief, implemented literally.

Why the bearing is not also multiplied by 5/4: a 14 px cap scaled to 17.5 px
would either blur or need a second resampling of the mask, which the brief
prohibits. Keeping the mask at 1:1 and only moving its origin is the only
integer-stable reading of "native glyphs, original logical positions".

## 3. Vertical fit

| Element | Physical rows |
| --- | --- |
| Mapped cell | 20 px |
| Baseline | 15 |
| Cap top | 1 |
| Descender bottom (`g`, `p`, `y`) | 18 |
| Accented cap top (`Ã`, `É`) | −2 (2 px above the cell) |

Accented capitals extend up to 2 physical pixels above the mapped cell. HGSS
window interiors and dialogue frames leave more than that in practice, but
this is an explicit review item: if a targeted window clips accents, the
options are a reviewed per-glyph baseline nudge or a window-specific variant,
not a global size change.

## 4. Shadow

The shadow is the *same* mask drawn 1 physical pixel right and 1 down, in the
shadow colour, immediately before the foreground. Because the foreground is
opaque, the overlap is covered without a second mask asset. This gives:

- one mask per glyph (no doubled atlas);
- one shadow run and one foreground run per compatible window;
- exact "shadow minus foreground" pixels for free.

Battle HP boxes and inverse text may need a different approved treatment; the
runtime exposes the offset and colours per text object rather than hard-coding
them.

## 5. Variants

| Variant | Status | Definition |
| --- | --- | --- |
| `standard` | generated | Galmuri14 mask, BDF bearings, original advance recorded |
| `numeric` | generated | same mask, centred in a fixed 10 px cell; used by the specialised numeric printers and HP boxes so digits cannot shift as values change |
| `compact` | **pending** | only justified where a measured HGSS advance is narrower than Galmuri14's ink; not generated yet because those advances come from the running game and any adaptation needs review |

No glyph is squeezed, resampled or bolded by the pipeline.

## 6. Spacing review evidence

`alignment_and_phase_4x.png` shows logical offsets 0–3 px, i.e. the four
physical phases produced by 5/4 mapping. All four are legible, letter spacing
does not collapse, and the one-pixel increments are visible without collisions
— so phase-specific bitmap variants are unnecessary for the first pass.

`sheet_dark_4x.png` and `sheet_light_4x.png` contain the brief's specimen
strings plus every supported accented character and symbol. Individual cases
are in `case_*.png` at 1× and 4×.

## 7. What the maintainer must approve

1. Standard text appearance.
2. Numeric text appearance (HP/PP/levels).
3. Letter spacing, including narrow (`i`, `l`) and wide (`M`, `W`) letters.
4. Line spacing in two-line dialogue.
5. Shadow treatment (1 px down-right, foreground over shadow).
6. Accented capitals extending 2 px above the mapped cell.
7. Compact-face policy: either accept standard metrics everywhere and fall
   back where the original advance is too narrow, or commission reviewed
   compact masks after Task 7 measurement.

Until this sign-off exists, the runtime default stays `text_renderer = legacy`
and no surface is enabled natively.
