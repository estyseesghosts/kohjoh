## Toolchain and environment facts (found today)

- MSYS2 strips `TMP`/`TEMP` and inline environment variables from child
  processes; native GCC then fails with "Cannot create temporary file in
  C:\Windows". Fixed in `src/compat/common.mk` and `tools/game/hgss_nitro.py`.
  Build options are therefore `--define NAME`, not environment variables.
- MSYS2 Python's `Path.symlink_to` silently **copies** directories; the SDK
  shim under `build/hgss-sdk` held stale copies, so SDK patches did not reach
  the libraries. Now Windows junctions via `cmd //c mklink //J` (MSYS turns
  a leading `/c` argument into a path; `//c` passes `/c`).
- Native tools cannot read `/c/...` paths inside response files: the link
  `.rsp` is written as `C:/...`.
- Azahar charges one tick per guest instruction (`[calib]` log line: 4.02
  ticks for a 4-instruction loop): its timings are instruction counts, a
  lower bound for O3DS cycles.
