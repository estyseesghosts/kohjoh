## What the hardware establishes

The steady Goldenrod windows process 51,310 FIFO words / 979 bulk calls per
game frame. The independent `[gamecpu]` median is approximately 37.2–37.5 ms
logic and 42.2–43.4 ms including publish work. This exceeds the ~33.4 ms game
budget even before asking whether each picture actually reached scanout.
The 139.7 s window contains 1,137 game updates for 600 submissions, with 537
pictures skipped. Its submission interval median is 84.5 ms.

The busy field remains CPU-bound. GPU draw suppression or late batch culling
alone cannot remove the FIFO work already done inside logic. Audio still
preempts the game on the same core; its cost is included in these wall times.

The 62-word source called from `NNS_G3dGlbFlushP` leads the per-list table in
every steady window: roughly 12–14% of sampled FIFO ticks, with zero replay
hits. It sends camera/projection, lights/materials and the base transform.
Source inspection explains the bypass: `NNS_G3dGeBufferOP_N` sends the opcode
through `NitroPort_GxFifoWord`, then its 62 parameters through a separate bulk
call. The latter starts inside a command and cannot enter the list cache.
The large cached scenery lists also spend substantial time copying/rebasing
vertices and indices. Smaller lit lists of 1,046/1,065 words repeatedly miss
their entry key despite having only one NORMAL command per sampled call.

The brief title samples include the known 3,081/1,432-word Ho-Oh lists with
rejection `0xa` (shared vertices and lighting/matrix dependence). This run
does not contain a long, steady title window. The SoulSilver logs contain
save-write stalls and lifecycle observations, not a Lugia performance profile.

## Changes and correctness boundaries

1. NitroSystem patch 0306 sends the contiguous 63-word global-state stream
   together when the command buffer is empty and unlocked. Pending-buffer or
   locked cases retain the original queueing path. Zero-parameter commands
   also avoid an empty `MIi_CpuSend32` call. The original DS branch is unchanged.
2. Lists containing only state events (no COLOR/NORMAL/TEXCOORD/VTX operations)
   retain their command layout and execute every state event
   against live parameters. Exact packed-opcode validation guards all retained
   offsets; changed layouts fall back to re-recording. Current matrix/light/
   material/test side effects still execute. Incoming vertex keys and repeated
   recording are unnecessary for these lists, even when their parameters vary.
3. Lit NORMAL commands are recognized as colour writes during dependency
   analysis. Four dependency sets cover the independent active/pending light
   enables, including in-list POLYGON_ATTR and BEGIN changes. Unlit normals
   and vertices before the first colour write still depend on incoming colour.
4. Matrix multiply uses the implicit affine column of 4x3/3x3 commands, with
   the original single fixed-point truncation after each dot product. Identity
   rotation, identity scale and zero translation avoid arithmetic; translation-
   only 4x3 products use the existing exact translation path. Projective right
   operands and all four matrix modes are covered by differential tests.

The state-only work also fixes an existing cache bug: restoring an old exit
snapshot could replace the incoming colour even when the current command
stream left it untouched. A native fixture distinguishes the old cached
result (`563022aa748c4bd0`) from both uncached decoders and the new cached path
(`04d5a8250aaaefff`). The new path retains live exit state. Tests alternate
lighting flags, material parameters, position tests, incoming colours, and
command layouts that switch between state-only and vertex operations.

Rationale: the measured source/copy/key costs above, plus Coffeepot CTR
`engineering/cpu-optimization.md` (reduce repeated integer work, compact hot
loops, small hot data) and `engineering/performance.md` (separate CPU work,
queue waits and GPU execution). No GPU ownership, audio placement, lighting
formula, visibility rejection or presentation policy was changed.

## Validation

and geometry differential corpora, profiled geometry accounting, 10,000 matrix
programs, cached/uncached dependency fixtures and replay/live verification.

95/95 applied. The diagnostic ARM FIFO wrapper remains 1,140 bytes, live
decoder 1,576 bytes, and FIFO/cache implementation 3,884 bytes (previously
4,980); these sizes do not certify total instruction-cache residency.

The global-state source changes from a 62-word split decode with zero hits
to a 63-word complete stream with every sampled call replayed (1,060/1,060
in this window). Its events still execute against current state. The replay
increase includes state-only streams and must not be presented as a retained
vertex-geometry hit-rate gain. The FIFO word count is 106 higher per frame
because the previously separately sent leading opcode now joins each bulk
global-state call; total command semantics have not grown by 106 commands.
The GPU triangle count, atlas work, tested screen appearance, and exclusive
GPU queue times remain consistent with the baseline. There are no missing
samples or dropped log lines in either A/B log.

The lit mesh key-miss word count stays approximately 1.55M/window: the refined
NORMAL dependencies do not explain this scene's measured improvement. Those
remaining misses need actual key-field attribution before further relaxation.
The title's matrix-dependent CPU lighting, copied scenery geometry and
offscreen CPU reconstruction remain larger follow-up opportunities. New
hardware speedup remains **O3DS_UNTESTED**; emulator timings are not O3DS
milliseconds. Collect the same hardware scene with the new normal build for
smoothness and diagnostic build for attribution.
