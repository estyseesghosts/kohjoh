# 2026-11-15: audio cost (chatlog11 plan, passes 1-5)

The software mixer took 17.2% of the O3DS application core in Goldenrod
(`a5f2d14` profile log `docs/logs/1`, 126 cycles per channel-sample, ~11
ADPCM channels, no capture). chatlog11's software plan was implemented in
full; CSND and core-1 audio were excluded by that plan and remain so.

## Results

Every mixer change is bit-exact against the revision before it (PCM output,
sound registers, sample memory and voice state), except the deliberate
default change from interpolated to held samples, whose held-sample path was
already covered.

| Commit | Change | Azahar Goldenrod ticks/channel-sample | Mixer core share (Azahar) |
| --- | --- | --- | --- |
| `4756c78` | measurement only | 107.6 | 14.8% |
| `6ca2ca9` | ordinary-routing fast path, prepared capture, packed output | 103.4 | 14.2% |
| `b6bad88` | ADPCM decoded as a run, then resampled; exact `/127` | 72.1 | 9.9% |
| `8705156` | held samples (DS) by default | 62.1 | 8.5% |
| `c64c07a`, `000080a` | 192-frame blocks, PKHBT output | (bench only) | |
| `ecb9c5a`, `3f673f1` | decoded-ADPCM cache | 48.0 | 6.6% |
| `52f78b6` | kernel flush of wave buffers | 48.0 | 6.6% |

Azahar ticks are instruction counts (`[calib]` 1.0), not O3DS cycles: the
O3DS figure includes cache misses and was 126 against Azahar's ~108 at the
start. Unicorn bench (`tests/native/sound_arm.py --reference 697df5a`,
HGSS-like workload): 80.8 -> 35.4 mixer instructions per channel-frame with
held samples (-56%), 79.7 -> 41.4 interpolated (-48%).

**O3DS: not measured.** Expected: roughly half the mixer's cycles, ~8% of
the core (~2.8 ms of each 33.4 ms game frame) back, if cycles follow
instructions. Two effects Azahar cannot show: I-cache (hot `mix_block` is
now 3.5 KiB, was 4.4 KiB; `NitroSound_Mix` 3.9 KiB) and D-cache (cached
PCM16 is read sequentially, one 32-byte line per 16 samples, against one
per 64 samples of ADPCM before). `[sndpmu]` measures both on hardware.

## Pass 1: measurement (`4756c78`)

New profile-build lines (see testing.md): `[sndstage]` sampled stage
ticks, `[sndadpcm]` ADPCM reuse, `[sndlock]` lock roles, `[sndout]` refill
deadline, `[sndpmu]` ARM11 counters, later `[sndcache]`. The underrun
counter counted the start-up wake-up; every hardware log's "1 underruns"
was that, not starvation.

Azahar Goldenrod findings: ADPCM render 44% and volume/pan 34% of mixer
ticks; 15-20 distinct sounds (39-53 KB compressed) started per 9.4 s
window, all decodes clean, >95% repeated work; the game thread never
waited on the sound lock (command holds p99 32 us, max 119 us); queue
low-water 1,376 frames (42 ms); 0 DSP drops.

## Pass 2: structure

- **Ordinary routing** (no capture, channels 1/3 mixed, outputs from the
  mixer: every HGSS log) adds all channels into one stereo pair; output
  stage reads it directly. Captures read their registers once per mix;
  feedback order unchanged. Output stage: one SSAT'd word per frame,
  master-volume division skipped at 127.
- **Held samples** are the default (GBATEK; melonDS treats interpolation
  as an enhancement). `--define KJ_SND_INTERPOLATE` restores linear
  interpolation (~6 instructions per channel-frame).
- **Block size 192** holds a whole 170-171-frame stretch: 96 -0.2%, 176/192
  -2.5%, 256 -2.4% against 128.

## Pass 3: ARM11 instructions

- The interleaved ADPCM loop spilled and cost ~31 instructions per decoded
  sample. Now: count = (phase + frames x step) >> 32 source samples are
  decoded in spans (to the next wrap or loop-start save) by a loop that
  does nothing else, then each frame picks or interpolates from the run.
  Blocks that end a sound or exceed the run buffer keep the old exact loop.
- `div127(x)`: SMULL by ceil(2^32/127) plus sign correction, exact for
  |x| < 38,000,000 (exhaustive test); operands < 4.2M. Volume and pan
  truncations stay separate.
- PKHBT packs the stereo word (GCC used UXTH+ORR).
- Left alone after objdump: `lerp` (5 instructions either way), no
  `__aeabi` division in hot loops, scale loop ~20 instructions with no
  stack traffic. 16-bit SIMD accumulation rejected (sums exceed 16 bits).

## Pass 4: decoded-ADPCM cache

Entries keyed by address and length: PCM16, step index every 8th sample,
copy of the compressed bytes. A block uses an entry only when the bytes
live decoding would read equal the copy and the voice's decoder and loop
state equal the entry's; else the entry is dropped and the block decodes
live. State is written back exactly. 384 KiB arena, oldest-first: 256 KiB
thrashed (bench: 92 evictions, 4x refills; Goldenrod's window ~280 KB).
Azahar verify build (`HGSS_SND_VERIFY=1`): 0 mismatches over 228,724
cached blocks, 99.8% of ADPCM blocks from the cache.

## Pass 5: integration

- Wave buffers are flushed with `svcFlushProcessDataCache` (coffeepot
  memory-and-cache: ~22 us vs ~58 us IPC for 1 KiB; 1-5 ms reported for
  `DSP_FlushDataCache` under core-1 load). `KJ_SND_DSP_FLUSH_IPC` for A/B.
- Lock: unchanged; no measured game-side stall.

## Tests

`build/diagnosis/venv/Scripts/python.exe tests/native/sound_arm.py`:
1,000 random full-chip register programs (every format, routing, bypass,
capture/reverb, loops, sounds shared between channels, bytes rewritten
inside playing sounds), the same with an 8 KiB cache, an HGSS-like bench,
and the exhaustive `div127` test. Deliberate mutations of the capture,
routing, PSG, noise, loop, output and every cache safety check change the
digest (the cached loop-save mutation needs 1,000 programs to show).
