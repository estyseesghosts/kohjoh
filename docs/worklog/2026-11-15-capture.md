# Decide capture before geometry production

The previous renderer decided to skip only at publish, after every game
frame had already decoded its geometry. The supplied Old 3DS window with
1,137 game updates and 600 submissions therefore paid the capture cost of
all 1,137 scenes. It does not establish that the entire logic time was
geometry, or that audio-preempted decoder maxima were geometry CPU time.

The previous publish boundary now selects capture for the next game frame,
using the same two-refresh lag threshold, script exemption and prohibition
on consecutive skipped pictures. The renderer honors that committed choice.
The first game frame captures normally. Falling behind during a frame can
only affect the next frame's choice, not discard a fully captured picture
at the last moment.

On a discarded scene, geometry commands still update matrices, lighting,
texgen, primitives, status counts and BOX/POS/VEC tests. GPU vertex writes,
cached vertex copies, clip-matrix float conversion and palette copies are
omitted. Existing retained lists can still replay; misses execute live
without recording unwritten vertices. Index and matrix-ID bookkeeping is
retained to preserve the current port's game-visible counts, including its
batch-local vertex duplication. This is a conservative first reduction of
capture work, not elimination of NNS traversal, FIFO parsing or CPU shading.

A discarded swap clears the build buffer without exchanging it with the
display buffer. The last complete scene survives unchanged. A partially
built scene keeps its capture choice through SWAP_BUFFERS, even if the next
game tick changes its request; a later publish can repeat the last complete
scene but cannot submit partially captured geometry. Existing DS V-blank,
simulation and audio scheduling are unchanged.

The profiled `[g3capture]` line reports captured/discarded swaps and the
discarded vertex/index workload. Read it alongside `[scene]` and `[gamecpu]`;
it counts scene construction choices, not observed LCD presentation.
