# Decide capture before geometry production

The previous renderer decided to skip only at publish, after every game
frame had already decoded its geometry. The supplied Old 3DS window with
1,137 game updates and 600 submissions therefore paid the capture cost of
all 1,137 scenes. It does not establish that the entire logic time was
geometry, or that audio-preempted decoder maxima were geometry CPU time.

The previous publish boundary now selects capture for the next game frame,
using the same two-refresh lag threshold, script exemption and prohibition
on consecutive skipped pictures. The renderer honors that committed choice.
The first game frame captures normally. Falling behind during a frame can
only affect the next frame's choice, not discard a fully captured picture
at the last moment.

On a discarded scene, geometry commands still update matrices, lighting,
texgen, primitives, status counts and BOX/POS/VEC tests. GPU vertex writes,
cached vertex copies, clip-matrix float conversion and palette copies are
omitted. Existing retained lists can still replay; misses execute live
without recording unwritten vertices. Index and matrix-ID bookkeeping is
retained to preserve the current port's game-visible counts, including its
batch-local vertex duplication. This remains the fallback for producers
that have not opted into the early gate. Field and title producers now skip
their scene traversal entirely, as described below.

A discarded swap clears the build buffer without exchanging it with the
display buffer. The last complete scene survives unchanged. A partially
built scene keeps its capture choice through SWAP_BUFFERS, even if the next
game tick changes its request; a later publish can repeat the last complete
scene but cannot submit partially captured geometry. Existing DS V-blank,
simulation and audio scheduling are unchanged.

The profiled `[g3capture]` line reports captured/discarded swaps and the
discarded vertex/index workload. Read it alongside `[scene]` and `[gamecpu]`;
it counts scene construction choices, not observed LCD presentation.

## Skip the producers, not just their output writes

Game patch 2007 calls `NitroPort_SkipSceneBuild` before field reset, camera
setup, map/prop traversal, NNS rendering, effects, draw tasks and swap.
Simulation, camera movement, map loading and animation updates remain in
the game update. Billboard retirement has an explicit update on skipped
ticks, preserving its FREE_REQUESTED to FREE_PENDING resource handshake.

The title queries the same gate once for Ho-Oh and sparkles. Their animation
frames and title substates still advance; geometry and swap are conditional.
The original DS build retains its original calls and signatures. Producers
not covered by this patch retain the state-preserving decoder fallback.
The gate refuses to interrupt a partially built scene.

`KJ_TEST_SKIP_CAPTURE` is a diagnostic-only alternating gate that also works
under scripted input. It is absent from normal builds. With profiling, the
producer counter reports FIFO words received on skipped game ticks.

Azahar 2126.2 integration verification, using a private executable/profile,
SD card and decomp checkout alongside the audio agent:

- Title: mixed intro/title window, 203 producer skips, **0 FIFO words**;
  captured 326 swaps, discarded 121, 0 discarded vertices/indices.
- Goldenrod: continued the benchmark save using
  `tests/inputs/goldenrod-producer-step.txt` in the lighting PR above this
  branch. First 600-submission window: **191 producer skips, 0 FIFO words**;
  captured 193 swaps, discarded 2, 0 discarded vertices/indices. Held game
  frames 1501 and 2101 show the city and both screens correctly.
- Neither run reported a cache-verification mismatch.

These runs used the stacked diagnostic artifact at `552a1a0`, with
`HGSS_PROFILE=on`, `KJ_DL_VERIFY` and `KJ_TEST_SKIP_CAPTURE`. Logs and held
images are in the geometry worktree under `build/azahar/gpu-lighting-title`
and `build/azahar/gpu-producer-field`. This proves omitted producer work in
the tested scenes; it does not measure an Old 3DS speedup. Hardware status:
**O3DS_UNTESTED**.
