# 2026-11-14: scene profiler audit

Reviewed the current source/history through `fc16401`, architecture, build,
testing, status, lessons, troubleshooting and the performance conversations,
especially chatlog10 and the corrections in chatlog09 / `fecd9ce`.
The last hardware logs still predate `fecd9ce`; older "logic per picture"
numbers often include two game updates. Do not repeat them as game CPU cost.

## Findings

Existing hardware evidence points primarily to CPU geometry work in busy
field scenes: ~4 ms completed GPU queues, tiny GPU wait, retained 2D, and
~51k FIFO words per game frame. It does not certify performance of the
current revision. The title's lit, matrix-dependent lists cannot replay
recorded vertex colours; CPU shading and live decoding remain plausible
causes. Ho-Oh's old missing-wing problem was a separate matrix-store bug.
Lugia uses the shared engine but needs its own measurements.

The existing random FIFO sampler and `[gamecpu]` were useful, but could not
name costly lists, quantify copied bytes, or preserve the original rejection
reason after a list became a fast "never" bypass. GPU timing read immediately
after FrameEnd could be stale or duplicated, especially when neither screen
changed. `[frame]` incorrectly described submission intervals as visible LCD
intervals. Logic alone also omitted renderer work from the game-frame budget.

The new offline census of `o3ds-log-0/dumps/f05000.kjd` reproduces chatlog06:

| Goldenrod captured workload | Count |
| --- | ---: |
| Batches / triangles | 124 / 8,370 |
| Trivially offscreen triangles | 7,451 (89.0%) |
| Whole batches outside a common plane | 72 |
| Triangles in those whole batches | 3,720 |

This establishes an opportunity, not a speedup. Rejecting draws after CPU
decoding cannot remove earlier FIFO work. The census uses actual widened
viewport/palette transforms and keeps W-mode depth semantics separate.
It does not measure occlusion, backface rejection, or GPU cost.

## Changes

- `[dltop]`: top 20 sampled FIFO sources/callers, decode/replay/nested copy
  ticks, maximum sample, copied bytes, normal requests/cache misses,
  persistent rejection masks and sampled periodic content rechecks. Bounded
  512-key storage; grouped short traffic; explicit omitted sample/tick totals.
  No per-opcode clocks, allocation or logging in this attribution hot path.
- GPU drawing samples now follow the next FrameBegin queue wait and name
  the previous non-empty game's frame/scene. Empty submissions do not count
  stale timers. First reporting window normally contains 599 completed
  queues rather than pretending all 600 current submissions finished.
- `[scene]`: submission/game/DS-scene identities, repeated scenes, empty
  submissions and observed GPU completion. Hitch detail includes scene ID.
  Submission cadence is explicitly labelled a proxy; LCD presentation remains
  unobserved. No Citro3D-owned event callbacks or pacing rules were changed.
- `[gamecpu] active logic+publish`: renderer-inclusive per-game-frame wall
  percentiles, including skipped pictures. Parent/child timing is documented.
- `tools/capture/g3_visibility.py`: offline JSON census and batch CSV.

The timing probes/table/counters compile out of the normal build. Diagnostic
formatting/reporting overhead and scheduler preemption still perturb the
profiled build. Copy is nested in replay; FIFO timings are nested in logic;
audio preemption is already included in those wall times. Never sum them.

## Hardware collection plan

Use matching baseline and `HGSS_PROFILE=on` binaries from this source, each
with its ELF and build-info. Keep edition, console/clock, location, camera,
save and recording duration fixed. Retain the whole log including run markers.

1. Warm up, then hold each scene for at least three complete reporting windows:
   Ho-Oh title; Lugia title; Goldenrod stationary; Goldenrod walking; edge of
   Goldenrod with city still loaded; just beyond its unload; Route 34 control.
   Note times for scene changes so mixed windows can be excluded. A window
   is 600 submissions and can last much longer than 20 s under overload.
2. Measure visible smoothness on baseline. Collect attribution with the
   profiled build. Avoid `KJ_G3_PROFILE` and `HGSS_A0_DIAG` in ordinary runs.
   Do not use an input script for real pacing tests: scripts disable skips.
3. Compare `[gamecpu] active` with the ~33.4 ms budget and `[pace]`/`[frame]`.
   Use `[scene]` and hitch IDs to distinguish skipped pictures, repeated DS
   scenes, and completed GPU queues. For actual displayed poses, use console
   video and melonDS frame captures; scene serials alone cannot prove motion.
4. Read `[g3sample]` and `[dltop]` with `[dlcov]`/`[dlwhy]`. High replay-copy
   share supports retained GPU geometry. High live decode with rejection bit
   8 and normal misses supports separating title geometry from CPU lighting.
   High remainder warrants key/recording profiling, not automatic blame on
   memcpy. Recheck counts plus swap ranges identify candidate 64-swap spikes,
   but do not themselves prove a temporal hitch correlation.
5. Capture dumps in separate runs (dump I/O stalls). Use the visibility census
   inside/outside Goldenrod to compare retained offscreen workload. A matching
   cache-off profile (`--define KJ_DL_NO_CACHE`) provides a cache A/B. Sampling
   is probabilistic; require enough observations before ranking close costs.

Remaining limits: FIFO residual does not separately time NNS model traversal
or animation production; PC sampling is still needed if work outside FIFO
dominates. Source pointers can be reused and immediate callers may resolve to
a shared DMA wrapper rather than an asset. Exact LCD presentation timestamps
need a separately validated presentation observer; the public queue wait only
establishes GPU completion. No new hardware performance claim is made here.

## Validation

Native differential checks pass: 100k sound programs, 2k geometry frames,
cached/live verification, and a profiled geometry build all retain the HEAD
output hashes. Mock-clock tests cover independent skipped logic, total active
work, exclusive nested stages and hitch scene IDs. Attribution tests cover
parent/child totals, omission accounting, reset, and never-list reason/recheck
persistence. Four synthetic visibility tests pass, and the captured Goldenrod
census matches the previously reported values above.

Both HeartGold builds and the SoulSilver diagnostic build package without compile errors or stale-library
fallback. ELF strings/symbols confirm `[dltop]`, `[scene]`, active-game-frame
reports and their state are absent from normal. The attribution table is
48 KiB of profiled-only BSS. ARM text sizes: FIFO wrapper 1,140 bytes, live
decoder 1,576 bytes, FIFO/cache implementation 4,980 bytes (not a measurement
of total working-set cache residency).

Azahar 2126.2, unscripted intro/title smoke
(`build/azahar/scene-prof-intro`, screenshots at 40/100/145 s): intro and
Ho-Oh render, audio runs, all new reports emit, and attribution omits zero
samples in every window. The first window contains 390 empty submissions
and only 209 completed queues: stale empty-frame drawing values are excluded.
In the steady title window ending at 141.3 s, 3,498 sampled FIFO calls spend
33,406,611 / 37,789,427 ticks (88.4%) in live decode. The two largest sampled
lists account for 42.9% of that total. They contain 3,081 / 1,432 words, have
zero replay hits in 10 samples each, and retain rejection mask `0xa`
(shared vertices plus lighting/matrix dependence). Normal-cache misses are
4,650 / 5,180 and 2,450 / 2,500 requests, respectively. The aggregate
`[dlwhy]` records no *new* rejection in this window, demonstrating why the
persistent per-list reasons matter. Scene serial advances every title
submission. These are emulator workload observations, not hardware time or
proof that every pose reached the LCD.

Goldenrod benchmark-save smoke (`build/azahar/scene-prof-goldenrod`, screenshots
at 150/200/230 s) reaches the expected city and emits multiple steady windows
at 51,310 FIFO words and 979 calls per game frame. No attribution omissions,
crashes or dropped log lines appear in either smoke log. This scripted run
verifies collection and rendering; skips are disabled, so it is not a pacing
or O3DS smoothness test.

In the Goldenrod window ending at 221.1 s, the 62-word source sent by
`NNS_G3dGlbFlushP` is the largest sampled entry: 1,018 samples, zero replay
hits, 8,561,182 raw ticks of 56,972,285 sampled FIFO ticks (~15%). That function
sends projection/camera, lights, materials and base-transform state. It is
not a retained vertex mesh; changing its cost needs state/matrix-path analysis.
Identical source contents do not justify skipping it: intervening models
change the current geometry state. A 5,201-word geometry source has 14 replay
hits in 14 samples but still copies 436,352 vertex/index bytes across those
samples. Nested copy accounts for 8,103,659 of 16,415,781 sampled replay ticks
in the full window. These observations distinguish repeated global-state
decoding from retained-geometry copying, rather than attributing every cache
cost to memcpy. Raw short-call timings can be probe-dominated; the remainder
also includes probes/preemption and must not be called exact cache overhead.
