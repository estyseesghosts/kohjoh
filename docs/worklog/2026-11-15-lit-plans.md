# Retain command plans for animated lit lists

The title's rejection mask `0xa` describes two separate blockers to baked
vertex blocks: strip vertices shared across matrix/state boundaries, and
lighting computed from a changing vector matrix. It does not mean the
immutable command sequence cannot be cached.

Lists rejected for baked replay now retain a bounded array of decoded
opcode/parameter offsets. A plan hit executes every command against current
state through the existing decoder dispatch, including matrices, normals,
texgen, strip assembly and game-visible tests. It skips packed-opcode parsing
and repeated parameter-width work. No lighting or entry-state key applies
to this form of replay. Swapping, incomplete streams and plans above 4,096
events retain the live path.

An exact source-word comparison guards each use, including the old
never-list fast bypass between 64-swap rechecks. Changed words decode live;
periodic rechecks can rebuild or promote the entry. The existing 6 MiB arena
and entry event storage own plans, with no per-frame allocation after warmup.
`KJ_DL_VERIFY` independently checks the retained operations and parameter
addresses against a fresh packed walk before executing them.

`[dlplan]` explicitly counts these as live command execution, not retained
mesh hits. Sampled time remains in decode; persistent rejection masks retain
their original meaning for the baked mesh cache.

CPU lighting also retains material/light-colour products until the relevant
material or light colour changes. Each enabled light computes its nine
terms lazily; disabled lights do no work. Emission, shininess, matrix
animation, light direction changes and normal changes do not invalidate
these colour-only terms. The
existing 5-bit product table, fixed-point vector/dot arithmetic, shininess
lookup, rounding and saturation are unchanged.

This implements command-plan caching and reduces repeated CPU lighting work.
It does **not** implement PICA vertex lighting or retain the lit meshes in GPU
memory. Those remain follow-up work: a DS NORMAL latches colour at command
time, so a GPU implementation must preserve that lighting context across
later matrix/material changes, explicit COLOR commands, and shared strip
vertices. The current clip palette alone does not represent that lifetime.

Rationale: Coffeepot CTR
[renderer architecture](https://github.com/estyseesghosts/coffeepot/blob/main/ctr/engineering/PICA200/renderer-architecture.md)
(compact specialized commands, retained versus immediate work),
[GPU rendering](https://github.com/estyseesghosts/coffeepot/blob/main/ctr/engineering/PICA200/gpu-rendering.md)
(uniform/state cost), and
[CPU optimization](https://github.com/estyseesghosts/coffeepot/blob/main/ctr/engineering/cpu-optimization.md)
(remove invariant work, check hot code size). No emulator result certifies
Old 3DS performance; audio preemption remains included in wall profiles.

Native differential validation passes against `4756c78`. The new 600-frame
lit corpus exercises all primitive types, shared vertices, changing vector
matrices, all lights, materials, shininess tables and texgen modes, with
source parameter/opcode mutations between content rechecks. Cached plans,
uncached execution, verify mode and the original decoder all produce
`c79962fa0fd30bf7`. Existing geometry, matrix, dependency, capture and
attribution regressions retain their hashes.
