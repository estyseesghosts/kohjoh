  LOTUS over MCP works. I can create sessions, step frames, capture screens, use
  savestates, set breakpoints and capture GPU draws. Captures come back as raw

  Starter particles (the bug the last agent left unfixed). The puffs are 3D
  particles drawn by the game's particle library, not 2D sprites. The particle
  code writes its geometry straight to the DS 3D hardware registers, and in the
  port those writes go into plain memory, so kohjoh never saw them. Breakpoints
  show the particle draw functions run every frame, while the dumped 3D scene
  for those frames has 0 batches and 0 vertices.
  - An earlier fix for the same problem (patch 2004) covered the game's own
    source but skipped lib/src, where the particle library lives. This likely
    also explains missing particle effects in battles and on the field.
  - The fix is new patch patches/pokeheartgold/2008-spl-send-the-particle-draw-s
    -direct-G3-command-regis.patch. It sends all 61 of those register writes
    through the port's hook; the DS build is unchanged. The patch check reports
    98/98 applied.
  - The previous agent's "oracle" renders only 2D layers, which is why it could
    never show the puffs.

  Battle stat arrows (masked onto everything except the Pokémon). kohjoh didn't
  implement the DS sprite-shaped window: the sprites that define it were
  dropped, and the area inside it was treated as outside. I implemented it in
  src/graphics/g2d/g2d.c using a stencil mask, which the coffeepot wiki
  recommends for sprite windows (ctr/engineering/PICA200/rendering-2d.md). It
  builds cleanly and leaves the intro pixel-identical. I haven't reproduced the
  battle yet, because the existing battle drive script still has placeholder
  timings.
