2. **Fix the 3D texture cache correctness bugs before reorganizing it.** The first semantic patch should be `src/graphics/g3d/textures.c`, because its current cache can return stale output. Format-5 compressed textures explicitly set `pal_len = 0` even though decoding later reads palette data selected by each 4×4 block; `still_valid()` consequently never checks that palette data. See [`textures.c:L215-L239`](https://github.com/estyseesghosts/kohjoh/blob/10444381a55f05cb4a42fcee8c52292943f3361a/src/graphics/g3d/textures.c#L215-L239) and [`textures.c:L378-L404`](https://github.com/estyseesghosts/kohjoh/blob/10444381a55f05cb4a42fcee8c52292943f3361a/src/graphics/g3d/textures.c#L378-L404). The second bug is transactional: on an existing entry, `kj_tex_get()` can overwrite the cached source shadow before palette access/decode succeeds, leaving the shadow describing new source bytes while the PICA texture still contains the previous decode. The affected hit/reconversion path is [`textures.c:L406-L517`](https://github.com/estyseesghosts/kohjoh/blob/10444381a55f05cb4a42fcee8c52292943f3361a/src/graphics/g3d/textures.c#L406-L517). Coffeepot requires failures to leave explicit coherent state and specifically says not to publish half-initialized/half-updated objects: [`c-style-guide.md:L251-L350`](https://github.com/estyseesghosts/coffeepot/blob/209c8ed42406453f8cff8c7f2df86c2723bc759d/c-style-guide.md#L251-L350).

   **Deliverables.** First add a native regression harness for `textures.c`; do not fix the code until the test reproduces the failure. The test must cover at least a normal indexed texture whose palette changes, a format-5 compressed texture whose **only** change is referenced palette data, a change in the compressed index data, an unmapped palette bank followed by the bank becoming available again, and a failed refresh followed by a later successful refresh. The cached result after recovery must exactly match a clean decode.

   For format 5, implement an exact conservative invalidation scheme rather than pretending `pal_len == 0` means “no palette dependency”. A reasonable bounded first implementation is a per-frame palette-generation check: retain a snapshot of the mapped texture-palette slots, bump a palette generation if a mapping or mapped palette contents change, and store the generation on successfully decoded format-5 cache entries. A format-5 entry whose generation differs must be decoded again. That may invalidate more compressed textures than strictly necessary, but it is correct and bounded. Measure the 96-KiB-ish palette comparison cost on O3DS before trying to make it cleverer.

   Make cache refresh transactional. Before modifying the entry's authoritative shadow, preflight all required texel/index/palette mappings. A decode must not be allowed to fail halfway because a required palette range was unavailable. Only after preflight and successful conversion should the entry's shadow bytes, palette snapshot/generation, `checked_frame`, and other validity metadata be published as describing the GPU texture.

   **Avoid.** Do not use a hash as the sole correctness check for palette contents. Do not simply re-decode every texture every frame. Do not allocate temporary heap buffers per `kj_tex_get()`. Do not change Morton layout, texture formats, filtering, wrap semantics, the last-hit/hint cache, cache capacity, or victim selection as part of this bug fix. Do not combine this with file decomposition.

   **Regression traps.** `still_valid()` deliberately avoids repeated work within a frame. Preserve that property. Existing ordinary palette formats must remain exact. A failed refresh must keep a known-valid old cache entry, not mark it as representing the new source. Profile `tex uploads` and `tex bytes compared` before/after; a correctness fix that explodes uploads in Goldenrod needs investigation rather than being accepted silently. This follows Coffeepot's “correctness before cleverness” and measurable-optimization rules at [`L17-L27`](https://github.com/estyseesghosts/coffeepot/blob/209c8ed42406453f8cff8c7f2df86c2723bc759d/c-style-guide.md#L17-L27) and [`L583-L591`](https://github.com/estyseesghosts/coffeepot/blob/209c8ed42406453f8cff8c7f2df86c2723bc759d/c-style-guide.md#L583-L591).

4. **Repair the crash logger so an exception cannot deadlock on the logger it interrupted.** [`crash.c:L48-L88`](https://github.com/estyseesghosts/kohjoh/blob/10444381a55f05cb4a42fcee8c52292943f3361a/src/diagnostics/crash.c#L48-L88) correctly recognizes that the normal log ring owns a lock, then calls `kj_log()` and `kj_log_flush_now()` anyway. `kj_logv()` takes that lock at [`log.c:L109-L138`](https://github.com/estyseesghosts/kohjoh/blob/10444381a55f05cb4a42fcee8c52292943f3361a/src/diagnostics/log.c#L109-L138). A fault while that lock is held can therefore deadlock the exception handler. Coffeepot's concurrency and ownership rules require explicit synchronization semantics and one clear owner for resources: [`c-style-guide.md:L449-L463`](https://github.com/estyseesghosts/coffeepot/blob/209c8ed42406453f8cff8c7f2df86c2723bc759d/c-style-guide.md#L449-L463), [`L251-L307`](https://github.com/estyseesghosts/coffeepot/blob/209c8ed42406453f8cff8c7f2df86c2723bc759d/c-style-guide.md#L251-L307).

   **Deliverables.** Remove normal ring-logger calls from the exception handler. The crash handler should build the register report, attempt the dedicated crash-file write on a best-effort basis, and then always reach `ERRF_ExceptionHandler`. If the crash-file write itself fails, that must not prevent the system error handler. Keep `s_in_handler` atomic so a recursive/second exception takes the shortest path.

   Separately fix normal logger flushing so there is exactly one serialized file-writer operation at a time. `flush_ring()` currently protects ring extraction but performs `fwrite`/`fprintf`/`fflush` after dropping the ring lock; meanwhile `kj_log_flush_now()` can call the same path concurrently with the writer thread. Add a dedicated flush/file lock, or otherwise guarantee that only one caller drains+writes at a time. Do not hold the producer ring lock during SD writes.

   Add a deliberate development-only crash test path or small test binary that faults in ordinary code and confirms: `crash.txt` receives a report, the normal 3DS error screen appears, and the console does not freeze inside the handler. Also deliberately invoke the handler while the logger's producer/flush path is active if practical.

   **Avoid.** Do not try to make the entire ordinary logger “exception safe”. Do not acquire the normal log locks from the exception handler. Do not perform elaborate cleanup from a corrupted process. Do not swallow the exception and continue.

   **Regression traps.** `fatal_screen()` still uses ordinary `kj_log_flush_now()` and must continue to work. Normal log-ring writes must remain non-blocking with respect to SD I/O; the frame thread must not start writing synchronously because the crash handler was fixed.

   Wait for outstanding GPU work before freeing buffers the PICA may still read. Kohjoh already does the `FrameBegin`/`FrameEnd` wait in normal renderer shutdown; preserve that semantic.

   **Avoid.** Do not create a generic “resource manager”. Do not move GPU buffers onto ordinary `malloc`. Do not transfer G3 storage ownership silently to `kj_g3.c`. The intended end state is not dramatically more abstract than Kohjoh is today. `renderer.c` should orchestrate presentation; G2D should be divided into screen composition, layer decoding, effects and retained-layer policy; G3 should have its independent math/cache/support responsibilities separated without fragmenting the hottest execution loop; resource ownership should be destroyable from every partial-init state; failures should propagate honestly; and the existing strong regression infrastructure should actually gate future changes.
